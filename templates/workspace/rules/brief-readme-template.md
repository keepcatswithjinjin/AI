# 需求 README 生成模板

> 本文件面向产出或维护 brief 的 Agent；执行 Agent 读取已经生成的需求 README，无需再读本模板。

## 一、生成约定

- 在实际开始产出方案时，为 `briefs/<类型>/<需求名>/README.md` 生成入口；新建需求仅登记索引/状态时不预建空目录或模板。
- 新建或实际维护需求 README 时按本模板组织；不因规则更新批量重写历史需求。README 只保留身份、阅读顺序和资料导航，不复制设计、执行进度、代码路径、分支或公共工具细则。
- 将 `<需求名>`、`<类型>` 替换为真实值；下面资料表是候选全集，生成时只保留实际存在的文档。后续新增、移除或重命名维护中文档时同步导航，不为保留链接而创建空文件。
- backend 保留后端计划，frontend 保留前端计划；cross 按适用文档保留契约与两端计划。交接和测试说明仅在存在时列出；缺失的必需方案应按生命周期报告，不以删掉导航掩盖缺项。
- 公共执行与能力路由唯一维护在 [执行入口](execution-entry.md)，各需求直接链接，避免工具规则在多个 README 中漂移。

## 二、README 正文模板

```markdown
# <需求名>

类型：<backend / frontend / cross>。

## Agent 接入

先读取 [工作站 执行入口](../../../rules/execution-entry.md)，按当前用户请求确定阅读、执行或 Review 职责；阅读资料本身不授权修改代码。

进入执行时，按执行入口加载适用角色、编码风格、项目规则、最新方案与交接；只读下表中当前阶段需要的实际文档，不通读整个需求目录。

## 当前资料

| 资料 | 读取时机 |
| --- | --- |
| [当前设计](spec/design.md) | 理解需求；实施或 Review 前读取，关键决定以此为准 |
| [接口契约](spec/api-contract.md) | 涉及接口协作时读取 |
| [后端计划](spec/backend-plan.md) | 后端实施；cross 接手时理解关联边界 |
| [前端计划](spec/frontend-plan.md) | 前端实施；cross 接手时理解关联边界 |
| [阶段交接](runtime/agent-guide.md) | 接手或继续中断任务时读取，并核验实时 Git 与验证证据 |
| [测试同事说明](spec/tester-note.md) | 提测、人工验证或维护此说明时读取 |

## 公共规则与按需能力

- [执行角色与必需上下文](../../../rules/execution-entry.md#二执行必需上下文)：按后端、前端或 cross 选择。
- [按需能力路由](../../../rules/execution-entry.md#三按需能力路由)：需要数据库/缓存、worktree、发布、云效或业务验证时，再读取对应行指向的细则。
- [需求生命周期与决策同步](../../../rules/task-lifecycle.md)：按当前操作读取相关章节。
- [阶段交接规范](../../../rules/handoff.md)：阶段结束或暂停前自动维护交接，无需询问。
- [代码位置与分支索引](../../WORKTREE-INDEX.md)：定位本需求后核验实时 Git，不从交接或会话名推断当前现场。

历史快照与备份不作为默认输入；README 不复制维护方案、进度或工具命令。
```

## 三、生成后检查

- 标题与目录的需求名一致，类型真实；不残留占位符。
- 解析相对链接，确认从需求 README 能到达 工作站 执行入口、生命周期、交接规范与全局代码位置索引；目录层级不同则调整相对路径，不照抄失效链接。
- 当前资料仅链接实际存在的文件，标准交接不存在但有兼容旧名时指向真实旧文件；下次交接维护后改为标准名。
- backend、frontend、cross 均能经统一入口找到适用身份；数据库等工具通过按需路由可发现，但不成为所有需求的启动必读。
