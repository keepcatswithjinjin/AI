# 首版人工代码 Review 导航

> 本规则只服务于“首版开发完成、尚未提交、由人工在 IDE 中核对代码”的阶段。它不是上线前 Agent Review，不输出风险结论、上线建议或测试结论。

## 一、触发条件

仅当用户明确要求首版代码 Review 导航图、未提交 diff 调用链图或在 IDE 中对照检查代码时生成。未收到明确触发时，禁止自动生成、更新或把它列为需求交付物。

生成前必须确认当前位于需求 worktree，范围是 `HEAD` 到工作区的未提交改动（含暂存与未暂存内容），且尚未进入提交、合并、发布或上线前 Review 阶段。无 diff、范围混入无关改动或基线不明确时停止并询问。

## 二、职责边界

| 项目 | 首版人工代码 Review 导航 | 上线前 Agent Review |
|---|---|---|
| 时机 | 首版开发完成、提交前 | 提交后或准备上线前 |
| 输入 | 当前未提交 diff 与直接调用链 | 指定基线到当前代码的 diff 与直接调用链 |
| 目的 | 帮人工快速定位入口和改动点 | 识别本次 diff 新引入的风险并给出证据 |
| 输出 | 代码导航、调用链、关键变更说明与流程图 | 后端/前端分离的 Review 报告和结论 |
| 禁止事项 | 风险评级、上线建议、测试通过声明、扩大检查范围 | 修改实现、代替人工合并冲突处理 |

两者不得互相替代。生成导航图不代表已经完成 Review；通过上线前 Review 也不代替人工首版核对。

## 三、产物位置与更新规则

```text
__WORKSPACE_ROOT__\artifacts\code-review\<需求名>\
├── code-flow.md
└── code-flow.html
```

- `code-flow.md` 是 IDE 核对导航；`code-flow.html` 是由 `diagram-design` 生成的可视流程图。
- 不写入 `briefs/`，不提交到业务仓库，不登记到 brief 索引。
- 每次生成都以当前未提交 diff 为准；只有用户再次明确要求时才覆盖更新。
- 用户提交、切换分支、合并或开始上线前 Review 后，该产物自动失效，不能作为后续 Review 证据。

## 四、生成步骤

1. 读取当前需求设计或用户确认范围，只用于理解本次改动目标；不复述完整设计。
2. 确认当前 `HEAD`、工作区状态和 diff 文件清单。
3. 追踪本次 diff 直接触及的主调用链：页面/接口/任务/消息入口 → 关键方法或组件 → 数据读写、外部调用或返回点。
4. 只保留帮助人工核对的主路径。超过 9 个节点、12 条连线或存在独立前后端路径时拆分图，不画全项目调用图。
5. 使用 `diagram-design` 生成自包含 `code-flow.html`：首选流程图；有明确多方交互时才选时序图。遵守插件的样式确认与几何校验要求。
6. 生成 `code-flow.md`，链接图文件并给出代码位置。生成后只说明产物和核对入口，不附带 Review 结论。

## 五、`code-flow.md` 最小结构

```md
# <需求名>：首版人工代码 Review 导航

## 核对范围
- 基线：`HEAD <commit>`
- 工作区：<worktree 路径>
- 本次未提交文件：<文件清单>

## 主调用链
入口（路径:行号） → 调用节点（路径:行号） → 本次改动点（路径:行号） → 返回点（路径:行号）

## 关键变更点
| 节点 | 原行为 | 当前变化 | IDE 核对重点 |
|---|---|---|---|

## 图文件
- `code-flow.html`

## 未纳入本次导航的范围
- <未被当前 diff 触及的路径；仅说明边界，不评价其正确性>
```

## 六、禁止规则

- 禁止根据方法名、字段名或注释猜测实际调用和数据语义；必须回溯实际调用、赋值或请求位置。
- 禁止把未触及的历史代码、测试分支内容、合并冲突内容或全项目引用关系塞进图中。
- 禁止运行提交、合并、发布、构建或测试来替代人工核对。
- 禁止输出“无风险”“可以上线”“测试通过”“逻辑正确”等 Review 结论。
- 禁止在没有用户明确触发时创建 `artifacts\code-review` 目录或任何图文件。
