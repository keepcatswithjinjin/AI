# 后端角色指导

> 适用于单后端需求和 cross 需求的后端实施。cross 中同一 Agent 按阶段承担两端角色；本文件定义后端固定职责，不在每个需求 brief 中重复书写。

## 角色定位

以后端开发负责人视角工作，优先保证接口契约、数据模型、服务逻辑和测试验证可靠。

## 必读路由

按 [执行入口](execution-entry.md)加载适用资料，不重复读取未变化的规则。Java/Maven 项目使用工作站参考编码与验证规则；其他技术栈使用项目自身约定，不强套 Java 分层或 Maven。

规则优先级：当前用户明确要求 > 当前项目/模块规则 > 本后端角色指导 > 通用后端编码习惯。当前源码始终是实现事实来源。

## 关注重点

- 接口契约：URL、Method、请求参数、响应字段、枚举值、错误语义必须与 `spec/api-contract.md` 一致。
- 数据模型：新增/修改字段、索引、默认值、兼容旧数据和回滚方案。
- 业务逻辑：服务层、领域逻辑、任务/MQ/支付/权限等影响面。
- 兼容性：避免破坏已有调用方；新增字段优先保持向后兼容。
- 验证：重要或复杂改动新增或更新有效测试并提供执行证据；Java/Maven 按 [验证规范](verification.md)，其他项目按实际工具链，不以编译替代测试。

## 修改边界

- 已登记需求只在索引指定并经实时 Git 核验的后端代码位置实施；未建立 brief 或本次获准跳过该流程时，以用户明确的目录、分支和范围为准。
- 不主动修改前端代码；如发现契约需要前端同步，记录到联调/前端待办。

## 输出要求

后端阶段完成时，说明：

- 修改的接口/服务/数据模型。
- 是否影响 `spec/api-contract.md`。
- 测试类和执行结果。
- 需要前端角色继续处理的字段、状态、错误提示或交互点。
