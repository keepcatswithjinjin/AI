# 工作站 需求执行入口

> 从需求 README 或项目入口接入执行上下文。先读必需资料，能力细则命中任务时再读；继承根 AGENTS 的公共边界，不套用根目录的新需求设计流程，也不全量加载其他规则。

## 一、确认本次职责

- 以用户当前请求确定职责。“读取/了解 brief”只做阅读；“开始实现/继续开发”进入执行；“上线前 Review”转到 [Review 角色](review-role-guide.md)，不沿用代码修改职责。
- 本入口不能扩大用户授权。执行中涉及已确认方案的变化，按 [生命周期第八节](task-lifecycle.md#八执行中的决策变化与提交前对齐)处理；提交、发布、数据写入、删除仍遵守对应授权。
- 用户已指定需求路径时，以该目录的 README 为入口，不再搜索其他同名或相似需求。未指定时，通过 [需求索引](../briefs/INDEX.md) 与 [代码位置索引](../briefs/WORKTREE-INDEX.md)核对当前 worktree；匹配不唯一时先澄清，不猜测。

### 执行决策边界

| 内容 | 执行权限 |
| --- | --- |
| 已确认的业务行为、接口语义、默认值、旧数据兼容及不改边界 | 不得自行改变；调整按生命周期第八节确认并回写 |
| 方法提取、局部命名、已有工具复用和测试组织 | 按项目规则及适用风格自行决定，不扩大改动范围 |
| 源码与方案冲突，或需要改变业务取舍 | 先核验真实入口；仍冲突则说明差异与影响，暂停受影响部分并确认；独立任务可继续 |

编码细则按下表路由，不复制进需求计划；未经确认的实现不能反向覆盖设计与契约。

## 二、执行必需上下文

已进入执行职责后，按以下顺序读取；同一对话已读且未变化的公共规则无需重复加载。

| 读取条件 | 资料 | 读取目的 |
| --- | --- | --- |
| 所有执行任务 | 当前需求 README 与实际存在的 `spec/design.md` | 目标、决定、不改边界与适用 DDL/发布范围；验收验证读计划，无 brief 时以当前明确范围为准 |
| 所有执行任务 | [生命周期](task-lifecycle.md)第一节授权边界、第七/八/十节；[交接规则](handoff.md) | 最新方案、决策回写、资料归属和阶段自动交接；不重走新需求登记或设计审批 |
| 所有代码修改 | 目标仓库根目录及修改路径上适用的项目/模块 `AGENTS.md`、`CLAUDE.md` | 项目规则、实际构建入口、项目知识导航；已有有效授权不重复索取 |
| 后端实施 | [后端角色](backend-role-guide.md)、需求后端计划及项目规则；Java/Maven 项目再读[编码风格](backend-coding-style.md)、[验证规范](verification.md) | 单后端及 cross 后端阶段适用；非 Java 项目使用其实际技术栈和验证入口，不套用 Java 分层 |
| 前端实施 | [前端角色](frontend-role-guide.md)、需求前端计划及项目前端约定 | 单前端及 cross 前端阶段均适用 |
| 涉及接口协作 | 需求中实际存在的 `spec/api-contract.md` | 字段、枚举、默认值、空值和错误语义 |
| cross 需求 | 两端角色、适用契约及两端计划 | 先理解共享边界，再由同一 Agent 按当前阶段实施，不因两端目录而默认拆分 Agent |
| 接手或继续中断任务 | 已有 `runtime/agent-guide.md`；旧名按生命周期兼容读取 | 停点、未完成事项和验证证据；重新核验实时 Git，不能用旧交接覆盖当前代码 |
| 确认代码位置 | [代码位置索引](../briefs/WORKTREE-INDEX.md)中本需求记录及实时 Git | 核对目标仓库/分支和工作区改动；未登记或有差异先核验，不能从会话名推断 |

首次执行前用一句话说明本次需求、执行角色和当前阶段即可，不输出冗长的逐文件阅读清单。缺少决定实施方向的方案、契约或定位信息时报告具体缺项，不创建空模板假装已齐全。

## 四、控制上下文与能力边界

- README 是导航，不是“把链接全部打开”的清单。按必需角色及当前意图读取，不递归通读 briefs、rules、knowledge 或 runtime；历史快照、日志和其他需求默认不加载。
- 先通过项目索引或精确检索定位相关资料，再核验当前源码和测试。出现事实缺口时可以沿证据追踪关联链路；路由不是禁止调查的封闭白名单，也不能把“少读”当作跳过必要依赖或风险核对的理由。
- 阶段切换、接续中断或发现冲突时，重新读取有变化的适用 spec 与交接；公共规则有更新时按最新版本执行。复用仍有效上下文，不每轮重复整套加载。
- 公共风格和工具细则只引用，不复制进 brief；需求特有的决定、约束和验证点保留在 spec，进度与停点保留在 runtime。
- 读取路由文件不会自动注册 MCP、启用 Hook 或增加文件/网络权限。工具缺失时报告具体不可用能力，不声称已经加载；不得为了接入而自行改写客户端或全局配置。
- 只为当前已需要的操作读取本地配置；不在启动时预读密钥、枚举所有数据库目标或发起外部连接。需要时按对应 Skill 的规则获取配置，不输出凭据。
